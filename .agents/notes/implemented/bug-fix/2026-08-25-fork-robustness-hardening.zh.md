# Agent Note: Fork 健壮性收口——配额闩锁清除、导出降级、查找防抖

Status: implemented

[English](2026-08-25-fork-robustness-hardening.md) | 中文

## Problem

2026-08-25 对 fork 扩展包的只读健壮性盘点发现三个值得修的缺口：

- **draft-keeper 的静默闩锁可能复活已清除的草稿。**任何存储失败（首因是配额耗尽）都会把镜像闩死，而闩锁后的 `remove()` / 空 `set()` 直接早退——于是闩锁之后发生的清除或发送把旧条目留在 localStorage 里，下次重载复活了用户眼看消失的文本，直接打破本包核心契约。既有的中途失败钉死从空存储起测，从未覆盖复活路径。
- **usage-stats 的 CSV 导出是裸平台链路。**`Blob` → `URL.createObjectURL` → 锚点 → 回收没有任何失败处理；对象 URL 被拦（强化隐私模式、扩展策略）时点击只剩静默加一条控制台错误。
- **find-in-chat 每次击键都全量重扫。**只有变更重扫有防抖；查询路径逐键重扫整个会话流，超长会话下可感知卡顿。

## Decision

三个最小修复，全部只动 fork 自有文件，各自沿用包内既有惯用法：

- **draft-keeper 在闩锁后保留一次清除尽力**（`draft-store.ts`）：闩锁后的 `remove()` / 空 `set()` 删掉内存条目并重试一次 `persist()`——配额挡住的 `setItem` 通常仍允许这次缩小重写或整键删除。护栏保证尽力不越界：只有从存储干净读出的映射才会被重写，读失败闩锁（映射为空）绝不猜测不可读记录。增长写入终身失效，模块头文档写明该职责。
- **usage-stats 包裹导出链路**（`UsageStatsSection.tsx`）：处理器捕获任何失败，经区块既有的错误行惯用法（`role="alert"`、`export.error` 语言键）呈现而非静默；成功导出清除该行。
- **find-in-chat 防抖查询重扫**（`find-controller.ts`）：输入框依旧逐键即时显示；扫描以与变更重扫相同的 200ms 跟随最后一次击键。导航按需冲洗挂起的重扫（`step`，Enter 路径改经它分发），键盘步进永远作用于当前查询；定时器路径保留原有的滚动到头行为，close/dispose 清理定时器。

## Testing

draft-keeper：闩锁钉死按新契约改写（增长失效、清除尽力），另加三例新钉死——配额闩锁后的缩小重写保留其他会话条目、读失败闩锁不触碰记录、以及客户端级端到端用例（先存储→配额失败→清除→模拟重载不复活）。usage-stats：一例新钉死——对象 URL 创建抛错时渲染错误行。find-in-chat：三例新钉死——快速连续击键只触发一次重扫（中间查询从未命中会话流）、步进冲洗挂起重扫且无残留定时器、close 取消挂起重扫；七处即时读取钉死改为在防抖外围 `vi.waitFor`，钉死内容不变。三个套件 155/155 通过。

## Alternatives considered

**闩锁清除时删除整条记录。**单键记录持有所有会话的草稿，裸 `removeItem` 会把其他会话的草稿连同被清除的一起毁掉；缩小重写保留它们。

**闩锁后恢复写入。**重试增长写入只会反复敲击已经拒绝写入的存储；增长写入的闩锁终身有效，只有清除职责在闩锁后保留。

**CSV 导出改走剪贴板。**复制到剪贴板自带权限失败面且不产生文件产物；锚点下载是既定形态，错误行现在覆盖它的失败。

**保持查找重扫同步。**浏览器原生查找确实逐键扫描，但那是原生实现；逐键全流 DOM 扫描正是防抖要消除的开销，导航前冲洗保证步进精确。

## Consequences

- 核心契约「不复活用户眼看消失的文本」在主导存储失败模式下成立；读写与缩小写入同时失败的存储仍无法清理，任何客户端代码都修不了这一点。
- 查找栏的计数最多滞后最后一次击键一个 200ms 防抖窗口；导航不受影响，因为导航前冲洗。
- 零组合面、零依赖、零上游文件变化；`.github/` 零触碰不变量维持。
