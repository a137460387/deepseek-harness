# Agent Note: Long-text paste folding as a fork browser plugin

Status: implemented

English | [中文](2026-09-13-long-text-fold.zh.md)

## Problem

Pasting a long plain-text clip into the Web composer floods the draft: the upstream `PASTE_COMMAND` handler inserts `text/plain` unconditionally with no length threshold (`packages/client/ui-conversation/src/client/input/editor/keymap.ts:156-163`), and the chat side renders sent user texts in full with no folding (`packages/client/ui-chat/src/client/chat/MessageItem.tsx:216-219`). The feature goal is Claude-web-style carding: the input shows a compact card, the sent message shows an expandable card, and the model receives the verbatim inline-paste text.

The double-source duplication check (recheck date 2026-09-13) came back **occupied on the community side, silent on the upstream side** — the first topic to carry a maintainer waiver for proceeding despite a non-empty community face (quality-first delivery on official seams). Community: official Discussions [#1031](https://github.com/deepseek-ai/deepseek-harness/discussions/1031) ships `long-draft-input` (input-side summary cards, display-only by its own stated principle; stale since its 2026-08-14 release day and predating the upstream Lexical composer its own limitation note describes as `textarea`/`backdrop`/`mirror`), and the dsplugin.app directory (13,258 entries) carries five more same-domain plugins — `dsh-paste-collapse` (marker placeholders expanded at send), `dsh-paste-code-block` (collapsible paste cards), `dsh-auto-paste` (long paste saved as an attachment), `dsh-longtext-input` and `dsh-web-text-drop` (long text to workspace files plus `@` references). `dsh-input-enhancement`, cited in the step-1 report as the closest send-side folding implementation, was downgraded to unverifiable: its repository now returns 404. Upstream: no first-party surface (no paste threshold, no chat folding, `isTrusted` absent from Lexical 0.49.0's paste path), while the generic file upload landed 2026-08-26 — the step-1 premise "the attachment pipeline is image-only, this needs `createDraftImages`" was corrected against the tree: the pipeline is media-neutral for file bytes (`FileBlock` in `packages/llm/llm/src/types.ts:84-88`), `createDraftImages` does not exist, and the corresponding private entry is `createDrafts` (`packages/client/ui-conversation/src/client/service.ts:308`, not on the frozen `IConversation` face). Step-2 verification then proved the load-bearing chain: the submit plane reads the draft at exactly one point (`packages/client/ui-conversation/src/client/input/facade.ts:397`), `setDraft` commits discretely and synchronously (facade.ts:286 with Lexical `_flushSync`), and document capture listeners precede both the element-level Lexical keydown and React's delegated clicks — so the placeholder can always be restored before the text is sent.

## Decision

`packages/extensions/long-text-fold` (`@deepseek-ai/dsh-client-long-text-fold`), a pure-browser fork-extension package (inert node half, `./invariant` companion, bilingual README, version pinned to root). Route B, form B-1 as approved: the text stays the message body and every seam is official.

- **Paste takeover, marker staging**: a document-level capture `paste` listener stages a threshold-crossing plain-text clip (2,000 characters or 50 lines) in localStorage keyed per session and puts a plain-ASCII `[LongText#N]` marker into the draft — via a marker-only synthetic `ClipboardEvent` re-dispatched onto the focused composer so the upstream paste path inserts at the caret (the global-paste forward pattern, `packages/extensions/global-paste/src/client/index.ts:86`), or via a public `setDraft` append when the composer is unfocused. The composition mounts this row before global-paste so the unfocused takeover sees the event first; the focused case is order-independent because global-paste yields to a focused composer. Files and mixed clips pass through untouched.
- **Submit interception, synchronous restore**: capture keydown/click listeners ahead of the composer's gestures — Enter on the composer, or the primary submit button identified by its `aria-label` against the upstream `input.send` / `input.send.steer` / `input.send.queue` labels read through the public locale service — expand every staged marker through the public `setDraft` (discrete, so the refreshed projection is what `facade.ts:397` reads), then let the native submit proceed. The submit plane has exactly one draft read and no second read (`packages/client/ui-conversation/src/client/input/machine.ts:145-160`), and `inputActions.submit()` has no production caller, so the two gestures are the complete bypass surface.
- **The chat fold decides on length, not the marker**: replacing the `conversation.chat.node` keyed renderers for `'user'` and `'steering'` (the catalog's documented replace-the-occupant mechanism), a text block at or above the render threshold folds in place — the real bubble clamps under a CSS max-height behind a bottom fade mask with a floating expand button, and the body projects the message's own text through the public `projectUserText` primitive. A forged or stale marker sends a short literal that cannot fold, so the renderer never trusts the marker and never touches storage; long texts from typing or other clients fold identically.
- **Fail-open at both failure points**: an unstaggable paste (oversized, quota, no storage) flows on to the native paste plus an error notice; a marker whose entry was evicted notifies without blocking and sends the literal short text. The staged store is LRU-capped (50 entries / 2M characters) with dead-session pruning and reload durability in localStorage.
- **Constants, not Config**: the thresholds and budgets are package constants with documented rationale — the text-file-cards precedent (`MAX_FILE_BYTES`); a Config surface would add a config-catalog face no browser-only fork package carries.

## Alternatives considered

**Route A — a real attachment (text file through the attachment pipeline).** Rejected for the primary: the model would receive a handle instead of the content (the projected path tells the model to read the file with tools), deviating from the Claude-web semantics the feature targets, and the chat side would still need the same `'user'`-key replacement because the shipped file card has no expand-to-read. A re-dispatch into the composer's own intake would work mechanically (no `isTrusted` gate in Lexical 0.49.0), but it couples the plugin to the internal branch behavior of the upstream `PASTE_COMMAND` handler more deeply than intercepting the event does. Maintainer-approved fallback should Route B's expansion mechanism prove unreliable in the field.

**B-2 — expand at the send layer (dsh-paste-collapse's architecture).** The community plugin wraps the runtime `conversation` service's non-interface `sendSession` member — a private-contract dependency that reaches around the frozen `IConversation` face, and its own bound signature has already been renamed once upstream (`imageIds` → `attachmentIds`). Within the fork's official-seams discipline there is no clean single-point send hook, so the gesture-pair enumeration (proven complete in step 2) was chosen instead; the plugin's localStorage-plus-host-route persistence idea was adopted in localStorage-only form.

**Marker-driven rendering.** Folding the chat side on marker presence would let the card title carry staging metadata, but it makes the renderer trust a user-editable token and needs storage access for the preview — a forged marker would render an empty card and a stale one a broken one. Length-based folding is self-healing (short literals render as text), storage-free, and consistent for long texts from any source.

## Consequences

- Long-paste authors get a compact composer, a staged-text dock with previews, and a chat history where long messages collapse in place behind an expandable clamp — while the model-visible shape stays byte-identical to an inline paste (one verbatim text block inside `user/message`).
- long-text-fold is the fork's tenth extension package: the seventh pure-browser member, the fifth `conversation.input.dock` consumer, the first `conversation.chat.node` keyed replacement (the `replaceRisk: 'shadows-shipped-ui'` seat — upstream user-bubble changes must be diffed against `fold-view.tsx` at each sync, now a FORK_NOTES checklist item), and the consumer that brings composer-guards to five.
- The contract specs turn upstream drift (Lexical update semantics, keymap routing, locale keys, mirrored copy, the slot catalog) into visible test failures at sync time.
- The submission echo shows the full text for the brief pre-admission window by upstream construction; the fold appears with the durable node. If upstream natively lands long-text carding, this plugin retires rather than competes (the standing step-7 rule).
