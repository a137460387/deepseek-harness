# Agent Note: 使用统计数据面——月度明细与 CSV 导出

Status: implemented

[English](2026-08-25-usage-stats-data-surface.md) | 中文

## Problem

使用统计标签页在日数据之外已经算出了月度聚合（`monthlyStats`），区块导语也承诺「按天与按月聚合」——但月度视图从未呈现：月度折叠在界面上没有座位，承诺只兑现了一半。这个面同样没有数据出口：数字只活在标签页里，想把它们带进电子表格（成本复盘、容量规划、汇报）的用户只能手工抄数。

## Decision

两个纯增量功能，都只在浏览器半侧、都建在本包既有的纯聚合之上——不动 host 侧、不加新依赖、不产生模型可见面（README 的 Model Experience 条目保持原样）：

- **月度明细块**：全量历史经 `monthlyStats` 折叠，在占比环形图之后呈现为紧凑的「月份 → 总量」列表，最新月在前，总量走与其余所有数字一致的 `formatTokens` 面。区块沿用标准块头与空态占位。
- **CSV 导出**：`dailyStatsToCsv` 把当前范围的日行渲染为 RFC 4180 文本（`day,total` 表头、每日一行、全量转义）；头部在「刷新」旁新增「导出 CSV」按钮，范围内无日行时禁用。下载构造 `text/csv` Blob，经临时锚点取对象 URL、文件名 `dsh-usage-<today>.csv`，点击后回收 URL。

导出即所见：按钮下载的正是趋势图所选范围（默认近 7 日）；全量历史只差一次切换。月度明细刻意不看范围——它回答「每月至今总量」，正如环形图回答「占比至今」。

## Testing

`tests/aggregate.client.spec.ts` 钉死 CSV 渲染：表头加按输入顺序每日一行、空范围只剩表头、RFC 4180 引号规则（逗号、双引号、换行）。`tests/section.client.spec.tsx` 钉死界面路径：双月历史下月度列表最新月在前；点击「导出 CSV」下载 `dsh-usage-<today>.csv` 且 blob 文本与预期 CSV 逐字一致、对象 URL 被回收；无日行时按钮保持禁用。包套件 66/66 通过。

## Alternatives considered

**CSV 带路由列**。系列键是开放集合（任意提供方或模型名），加宽列意味着动态表头与消费方靶位漂移；`day,total` 是诚实的最小集，路由拆分留在标签页内。已作为导出限制记入 README。

**无视范围选择器导出全量**。导出屏幕所见可预期，且按钮与其所指数据相邻；全量下载经「全部时间」范围一步可达。先选范围避免了意外的批量下载。

**月度图表而非列表**。趋势图已承载跨日的形状；月度问题要的是精确总量，列表无需调色板、坐标轴与图例机构即可回答。

## Consequences

- `monthlyStats` 从此有了界面座位，导语「按天与按月聚合」完全成立；原先仅测试引用的聚合同时被单测与渲染块钉住。
- 日级总量可以 CSV 形式离开标签页；导出仅覆盖范围内的 `day,total` 行（路由拆分留在标签页），README 的限制小节现已写明。
- 组合面零变化：设置区块 slot、投影单元、模块请求均未触碰，因此无需任何组合或供给行调整。
